Project: RV-DIS: RISC-V Dual-Issue Processor
(RV32I scalar; in-order even/odd dual-issue)

RISC-V 32-bit instructions formate

RV32I Instruction Set Architecture Deisgned:

    | Design choice              | Rationale                                              |
    |----------------------------|--------------------------------------------------------|
    | Fixed 32-bit instructions  | Simpler fetch/decode; no mixed instruction lengths     |
    | 3-address registers rd/rs1/rs2 | Fewer insns than 2-address style                 |
    | Uniform field placement    | Same bit positions for rs1, rs2, rd; imm sign-extended |
    | Compiler / OS target       | Sufficient for codegen and modern OS environments      |
    | Minimal hardware footprint | RTL verifiable via Yosys (scripts/run_yosys.ps1)       |

S1_Fetch:

    Fetch Core Structure:                                   [Verified - Done]   [Proof - TBD]
        Path: `rtl/s1_fetch/fetch_core_struct.sv`

        Instantiates pc, instruction_cache, target_buffer, and pc_selector.
        Registered pc0/pc1 feed I$ and BTB; BTB targets and execute recovery feed
        pc_selector; selector pc0_out / pc1_out / per-lane spec flags feed pc.
        Mode (+4/+4 vs +8/+8) is computed inside pc from spec0_in ^ spec1_in.
        Nested-speculation freeze enters as spec0_stall / spec1_stall from decode
        target_predict (not generated inside pc_selector). External predict/recover
        and WB train ports stay at the struct boundary. Struct i0_valid / i1_valid
        come from the I$ entry valid bits (instruction present); BTB hit stays
        internal. Predict-taken is driven from outside.

        Per-lane speculation (design rule):
            Speculative fetch is lane-owned. If I0 takes a branch, I0 follows the taken
            path and holds spec0; if I1 takes a branch, I1 follows the taken path and
            holds spec1. There is no forced remapping that always puts the taken stream
            on I0 and fall-through on I1. That keeps IF/ID/decode spec0_en / spec1_en
            aligned with which slot actually speculated (so a branch fetched in I1 does
            not falsely mark I0 as speculative).

        0. Structure and Specification:

            The PC unit is a registered dual-issue address generator. It owns two 32-bit
            byte addresses, pc0_out and pc1_out, for the I0 and I1 fetch lanes, plus two
            registered speculation flags (spec0_out / spec1_out) that record whether
            each lane is currently on a speculative path. The flags are independent:
            spec0 tracks I0; spec1 tracks I1. The module does not decode branches or
            read the BTB. It only (1) aligns pc0_in / pc1_in to 4-byte boundaries,
            (2) computes local mode from next-spec bits and adds the selected increment
            when enabled and not stalled, and (3) latches PCs and spec flags on the
            clock edge. Bases and next spec bits come from pc_selector. Stall is
            dispatch_stall | spec0_stall | spec1_stall (decode nested-speculation and
            dispatch back-pressure). On reset, pc0_out <= RESET_PC, pc1_out <= RESET_PC+4,
            and both spec flags clear.

        1. Dual PC adder with mode selection:

            After alignment, pc0_a = {pc0_in[31:2], 2'b00} and pc1_a = {pc1_in[31:2], 2'b00}.
            Local: mode = spec0_in ^ spec1_in (exactly one next-spec lane).
            When enable is high and neither stall is asserted, mode selects the increment:

            | mode | Name                  | pc0_next  | pc1_next  | Use case                                   |
            |------|-----------------------|-----------|-----------|--------------------------------------------|
            | 0    | sequential dual-issue | pc0_a + 8 | pc1_a + 8 | straight-line; next 8-byte bundle          |
            | 1    | speculative / split   | pc0_a + 4 | pc1_a + 4 | each lane advances its own stream by +4    |

            If enable is low or dispatch_stall | spec0_stall | spec1_stall is high, PCs
            and spec flags hold; the pair does not move.

        2. Branch Speculation and Stalls Behavior:

            Speculation is a cross-module contract. pc_selector drives pc0_in / pc1_in
            and spec0_in / spec1_in; `pc.sv` latches and feeds spec0_out / spec1_out
            back to the selector. Nested-speculation stall is produced in decode
            target_predict and enters here as spec*_stall (not from pc_selector).
            Because each flag is lane-local, decode nest-stall for lane N only trips
            when that same lane's spec_n is already set.

            | Signal          | Direction      | Role                                                           |
            |-----------------|----------------|----------------------------------------------------------------|
            | spec0_in/1_in   | sel -> pc      | Next per-lane speculative state; latched on enabled update     |
            | spec0_out/1_out | pc -> sel      | Registered flags; fed back for next-spec computation           |
            | spec0/1_stall   | decode -> pc   | Freeze PC when a branch/jump arrives while already speculative |
            | dispatch_stall  | dispatch -> pc | Freeze PC independently; holds PC and spec flags               |
            | spec0/1_in      | sel -> pc      | Also form mode: XOR => +4/+4; equal => +8/+8                   |

            On recovery, pc_selector clears both next-spec bits (mode=0) and reloads
            bases past the resolved branch (execute+4 / execute+8). Pipeline flush lives
            in decode/dispatch, not in `pc.sv`.

        0. Structure and Specification:

            pc_selector is a purely combinational routing block among the registered PC
            pair, BTB targets, and execute recovery. It does not apply the sequential
            / split stride; that is `pc.sv`'s job (local mode from next-spec XOR).
            Each cycle it drives aligned pc0_out / pc1_out as the bases `pc.sv` will
            add to, plus next per-lane speculation flags. It does not generate a fetch
            stall: nested speculation is blocked in decode by target_predict
            (spec_stall -> pc.spec*_stall).

            Taken vs fall-through is per predicting lane (not a fixed I0=taken /
            I1=fall-through convention). A predict on I0 steers I0's base to the
            target; a predict on I1 steers I1's base to the target.

        1. Dual PC Selection Priority without speculation:

            Default (no predict, no recovery): pc0_out = align(pc0_in),
            pc1_out = align(pc1_in); `pc.sv` then applies +8/+8 (mode=0).

            Predict mux (recovery overrides; see §4):

            | Condition           | pc0_out                  | pc1_out                         |
            |---------------------|--------------------------|---------------------------------|
            | i0_pred && i1_pred  | align(i0_pc_target)      | align(i0_pc_target) + 4         |
            | i0_pred only        | align(i0_pc_target)      | align(pc1_in)                   |
            | i1_pred only        | align(pc0_in)            | align(i1_pc_target)             |

            i1_pred-only: only pc1_out updates to the branch target (spec path stays on
            I1); next-spec becomes asymmetric so `pc.sv` mode=1 (+4/+4). pc0_out is
            left as align(pc0_in) — by the time predict feeds back, that registered pc0
            is already the next-cycle base from the prior +8 advance, so I0 does not
            need an extra +4 nudge here.

        2. Control signals:

            | Output     | Asserted when                                         | Effect on `pc.sv`                 |
            |------------|-------------------------------------------------------|-----------------------------------|
            | spec0_out  | (i0_pred_taken | spec0_in) && !recover_any            | latched; forms mode via XOR      |
            | spec1_out  | (i1_pred_taken | spec1_in) && !recover_any            | latched; forms mode via XOR      |

            recover_any = i0_brch_recover | i1_brch_recover.
            Speculation is sticky per lane: only the predicting lane's flag ORs in;
            the other lane is not forced speculative. Recovery clears both next-spec
            bits so `pc.sv` mode goes to 0.

        3. Branch Speculation Behavior:

            | i0_pred | i1_pred | next-spec (ex. sticky 0) | pc mode | increment | Notes                         |
            |---------|---------|--------------------------|---------|-----------|-------------------------------|
            | 0       | 0       | 0 / 0                    | 0       | +8 / +8   | straight-line or recovery     |
            | 1       | 0       | 1 / 0                    | 1       | +4 / +4   | I0 taken; I1 falls through    |
            | 0       | 1       | 0 / 1                    | 1       | +4 / +4   | I1 taken; pc0 unchanged       |
            | 1       | 1       | 1 / 1                    | 0       | +8 / +8   | both taken; I0 target pair    |

            Nested branch/jump while that lane is already speculative is stalled by
            decode target_predict (spec_stall), which freezes `pc.sv` via spec*_stall;
            this module does not assert a stall of its own.

        4. Branch Recovery Behavior:

            Recovery has highest priority; resume past the resolved branch:

            | Priority | Condition          | pc0_out                         | pc1_out                         |
            |----------|--------------------|---------------------------------|---------------------------------|
            | 1        | i0_brch_recover    | align(i0_pc_execute) + 4        | align(i0_pc_execute) + 8        |
            | 2        | i1_brch_recover    | align(i1_pc_execute) + 4        | align(i1_pc_execute) + 8        |

            Recovery clears next-spec (mode=0); `pc.sv` resumes +8/+8 from the
            post-branch pair on the next enabled update. Flush remains outside pc_selector.

        0. Structure and Specification:

            instruction_cache is the fetch-stage dual-port instruction store for the
            32 KiB RV32I I$ space (rv_dis_pkg::I_SIZE). The program counter is
            byte-addressed
            (ADDR_UNIT_BITS=8), while each bank cell holds one aligned ILEN=32
            little-endian instruction word plus a valid bit (a 33-bit packed entry
            through cache_pkg). INDEX_W = PC_INDEX_AW = 13 selects among 8192 logical
            slots using PC[14:2]. Lookups are combinational; clk and rst_n clear the
            bank on reset. Until sequential miss/refill exists, simulation
            (instruction_cache_tb) or an external loader preloads valid entries. The
            module exposes pc0/pc1 in, instr0/instr1, and i0_valid/i1_valid out and
            does not yet arbitrate misses, refill, or coherence.

        1. 2-way Set-Associative Bank (4-byte instruction word per entry):

            The bank is organized as WAYS=2 (WAY_AW=1, SET_AW=12, SETS=4096): 4096
            sets of two ways, for 8192 x 4 B = 32 KiB of instruction payload.
            cache_pkg::pc_set / pc_way map each fetch PC to one cell with way =
            PC[2] and set = PC[14:3], so each entry stores {valid, instr[31:0]} -
            one full RV32I word, not a single byte. Two-way associativity is chosen
            as the minimum that matches dual-issue fetch: a straight-line pair
            (pc, pc+4) are consecutive word addresses that differ only in PC[2], so
            they land in the same set on ways 0 and 1 and can be read in parallel
            without a same-way bank conflict. An 8-byte aligned dual-issue bundle
            therefore maps onto both ways of one set, which is exactly the
            (pc0, pc1) window produced by `pc.sv`. Each port still indexes
            independently, so any pc0/pc1 pair is legal; the two-way layout makes
            the common sequential dual-fetch case a natural dual hit inside one set.

        2. Combinational Dual Instruction Address Read:

            Both ports read independently in the same cycle. Port I0 indexes
            bank[i0_lookup_set][i0_lookup_way] from pc0; port I1 indexes
            bank[i1_lookup_set][i1_lookup_way] from pc1. Each lookup is
            combinational through cache_way_read: if the selected entry's valid bit
            is set, instrN is the stored word; if valid=0 (cold miss), the default
            data 32'h0 is returned. i0_valid / i1_valid export that same entry valid
            bit so a cold miss is distinct from a stored all-zero word.

            Because indexing is direct-mapped by PC set/way (not tag compare), each
            PC maps to exactly one bank location. Dual fetch therefore works for any
            pc0/pc1 pair, including sequential pairs (pc, pc+4) and identical PCs on
            both ports. The two reads do not block each other; they are two parallel
            cache_way_read calls on separate bank cells. In fetch_core_struct, pc0 and
            pc1 from `pc.sv` drive instr0/instr1 into the decode stage on the same cycle
            as the address presentation.

        3. Sequential Cache Instruction Miss (Working Progress):

            Not implemented in current RTL. Planned: sequential miss detect, external
            memory refill, valid install, and fetch stall until both requested lines
            are present.

            input  wire        clk,
            input  wire        rst_n,

            //internal controls
            input  wire        i0_valid_wb,
            input  wire        i1_valid_wb,

            //input data
            input  word_t      i0_pc,
            input  word_t      i1_pc,
            input  word_t      i0_pc_wb,
            input  word_t      i1_pc_wb,
            input  word_t      i0_pc_target_wb,
            input  word_t      i1_pc_target_wb,

            //output data
            output wire        i0_valid,
            output wire        i1_valid,
            output wire [31:0] i0_pc_target,
            output wire [31:0] i1_pc_target

        0. Structure and Specification:

            target_buffer is the fetch-stage branch target buffer (BTB). Lookups are
            combinational dual read with same-cycle writeback forwarding; the bank
            trains on negedge clk. The
            module does not decide predict-taken: it only reports per-port hit flags
            (i0_valid / i1_valid) and predicted targets (i0_pc_target / i1_pc_target)
            for downstream fetch/select logic. Execute-stage i0_valid_wb /
            i1_valid_wb qualify training writes that install or overwrite the target
            for the branch PC at WB. clk and rst_n clear the bank on reset.

        1. 16-way Set-Associative Bank (4-byte aligned target per entry):

            The bank is organized as WAYS=16 (WAY_AW=4, SET_AW=9, SETS=512): 512
            sets of sixteen ways, for 8192 logical slots over the same INDEX_W=13 /
            PC[14:2] space as the 32 KiB I$. Each cell is a 33-bit packed entry
            through cache_pkg: {valid, target[31:0]}, where the payload is one
            imm_align4 branch target (not an instruction word). cache_pkg::pc_set /
            pc_way map each lookup or train PC to one cell. Higher associativity than
            the I$ (16-way vs 2-way) gives more distinct branch PCs room in the same
            address window without changing the PC index width. Each port still
            indexes independently, so any i0_pc / i1_pc pair is legal.

        2. Combinational Dual Read with Forwarding:

            Each cycle both ports look up independently from i0_pc and i1_pc. For each
            port, way_with_forward selects bank[set][way] unless a valid WB in the same
            cycle targets that same set/way; then the incoming WB entry wins (I0 WB
            checked before I1 WB). i0_valid / i1_valid are the forwarded entry valid
            bits (entry[DATA_W]) and are independent: a miss or stored valid=0 on one
            port clears only that port's i*_valid. cache_way_read returns the stored
            target when valid=1; on miss (valid=0) it returns 32'h0 for that lane while
            i*_valid stays 0. Lookups are combinational; outputs update in the same
            cycle as the presented fetch PCs.

        3. Sequential Falling-edge Dual Writeback:

            Training commits on the falling clock edge when i0_valid_wb or i1_valid_wb is
            set. The write index is derived from i0_pc_wb / i1_pc_wb; the stored data is
            imm_align4(i0_pc_target_wb / i1_pc_target_wb) with valid forced to 1 via
            cache_set_write. Dual WB in one cycle can update two distinct slots; if both
            trains map to the same set/way, both nonblocking writes fire and the I1
            update is the final value in that slot. Because forwarding is evaluated
            before the edge, a train visible on cycle N is readable on port outputs
            (i*_valid and i*_pc_target) in cycle N even though the bank register updates
            after the edge; the read path always sees the freshest hit/target for
            pc_selector in fetch_core_struct.

        0. Structure and Specification:

            if_id is the pipeline register between fetch (IF) and decode (ID). An
            instruction is in IF or ID, not both; this module is the cycle
            boundary where the dual-issue pair is captured for decode. It is a single
            registered stage with no combinational decode; it stores and forwards
            per lane: instruction word, fetch PC, predicted branch target, slot valid,
            and speculation enable. pc_target_* is carried alongside the insn so ID and
            later stages can compare against resolved execute targets for mispredict
            recovery. clk/rst_n/enable are the global pipeline controls; flush and stall
            are stage-local back-pressure and redirect inputs from upstream fetch or
            downstream decode/dispatch.

        1. Dual Issue Input and Output:

            Both lanes update together on the same conditions. Fields per bundle:

            | IF/ID field (input)  | Source (IF stage)     | ID output (latched)   |
            |----------------------|-----------------------|-----------------------|
            | i0_instr_if          | instruction_cache I0  | i0_instr_id           |
            | i1_instr_if          | instruction_cache I1  | i1_instr_id           |
            | i0_pc_if             | pc pc0_out            | i0_pc_id              |
            | i1_pc_if             | pc pc1_out            | i1_pc_id              |
            | i0_pc_target_if      | target_buffer I0      | i0_pc_target_id       |
            | i1_pc_target_if      | target_buffer I1      | i1_pc_target_id       |
            | i0_fetch_valid       | I$ i0_valid           | CE + i0_valid_id      |
            | i1_fetch_valid       | I$ i1_valid           | CE + i1_valid_id      |
            | spec0_en_if          | fetch spec0_en        | spec0_en_id (if hit)  |
            | spec1_en_if          | fetch spec1_en        | spec1_en_id (if hit)  |

            Per-lane clock enable: when enable && !stall, a lane clocks instr/PC/
            pc_target/spec only if i*_fetch_valid=1 (instruction_cache hit). A miss,
            reset, or flush writes an architectural NOP bubble: instr = INSTR_NOP
            (addi x0, x0, 0 = 32'h0000_0013), PC/target = 0, valid = 0, spec = 0.

        2. Stalls and Flush control:

            Update priority in the always_ff block (highest wins on a clock edge):

            | Priority | Condition        | ID register behavior                    |
            |----------|------------------|-----------------------------------------|
            | 1        | !rst_n           | both lanes -> INSTR_NOP bubble          |
            | 2        | flush            | both lanes -> INSTR_NOP bubble          |
            | 3        | enable && !stall | capture on hit; miss -> INSTR_NOP bubble|
            | 4        | otherwise        | hold previous ID state                  |

            flush empties the stage on mispredict or redirect so decode does not consume
            stale instructions after fetch realigns. stall freezes without clearing. IF
            may continue presenting, but ID keeps the prior pair until back-pressure
            releases. If enable is low, no advance occurs even when stall is low.

        0. Structure and Specification:

            decoder is a purely combinational RV32I scalar decode block for one
            instruction slot. It accepts a single 32-bit instr word and drives decoded
            opcode/funct3/funct7, GPR indices (rd, rs1, rs2), a sign-extended immediate,
            and control qualifiers for downstream register read, branch prediction, and
            dispatch. Field extraction and legality tables live in decode_pkg; the
            module itself is only wiring: raw opcode/funct3 are sampled first, then
            GPR-specific decoders zero unused register fields per opcode rules. Control
            qualifiers driven per slot:

            | Signal    | Definition                                              |
            |-----------|---------------------------------------------------------|
            | valid     | insn is in the implemented RV-DIS scalar subset           |
            | brch_en   | valid && opcode in {BRANCH, JAL, JALR}                   |
            | jump_en   | valid && opcode in {JAL, JALR} (unconditional jumps only)|
            | rs1_use   | operand needs GPR rs1 read                              |
            | rs2_use   | operand needs GPR rs2 read                              |
            | reg_write | insn writes rd (x0 suppressed downstream)               |

            jump_en is distinct from brch_en so target_predict can treat direct jumps
            separately from conditional branches. The decoder does not read the register
            file, predict targets, or issue to execution; that integration is in
            decode_core_struct and dispatch.

        1. Two Decoders for Instruction Parallelism:

            Dual issue replicates decoder twice in s2_decode_struct (u_dec_i0 /
            u_dec_i1). Both run in parallel with no cross-coupling. Per-lane wiring
            inside decode_core_struct:

            | Lane | Decoder   | target_predict      | IF/ID inputs              | state_buffer |
            |------|-----------|---------------------|---------------------------|--------------|
            | I0   | u_dec_i0  | u_target_predict_i0 | i0_pc, i0_pc_target       | i0_target_state |
            | I1   | u_dec_i1  | u_target_predict_i1 | i1_pc, i1_pc_target       | i1_target_state |

            Each decoder exports lane_sel, opcode bundle, imm, valid, brch_en, jump_en,
            rs1_use/rs2_use, and reg_write. GPR read addresses are exported as
            i0_rs1_addr / i0_rs2_addr and i1_rs1_addr / i1_rs2_addr for later stages
            (issue RF); decode_core_struct does not instantiate register_file.
            state_buffer also lives here. Pairing legality and which lane may fire
            are decided later in dispatch, not inside `decoder.sv`.

        2. Instruction Lane Differentiation:

            lane_sel tags which execution lane owns the opcode class:

            | lane_sel | Execution lane | Opcode classes                          |
            |----------|----------------|-----------------------------------------|
            | 0        | I0 (even)      | OP, OP-IMM (scalar ALU)                 |
            | 1        | I1 (odd)       | LOAD, STORE, BRANCH, JAL, JALR, LUI, AUIPC |

            Unknown opcodes default lane_sel=0 but valid=0 so dispatch can squash
            illegal slots. Supported branch compare subset: BEQ, BNE, BLT, BGE; memory:
            LW, SW. rs1_use and rs2_use mark which source operands need a later
            register-file read (issue stage); reg_write suppresses writes to x0.

        0. Structure and Specification:

            state_buffer is the branch-direction predictor table (BHT). Instantiated
            inside decode_core_struct as u_state_buf. It stores a 2-bit saturating counter
            state (br_state_t) per branch PC, indexed like the BTB: INDEX_W = 13 over
            PC[14:2], 8192 slots, 512 sets x 16 ways (see shared geometry table in
            S1_Fetch). Each bank entry is 33 bits: valid plus 2-bit state. Set/way
            decode uses cache_pkg::pc_set and cache_pkg::pc_way. Miss (valid=0) defaults to
            DEFAULT_STATE (2'b10, weakly taken). i0_brch_en / i1_brch_en gate
            whether a lane performs a real lookup; non-branch insns drive
            DEFAULT_STATE on the outputs without treating the bank as taken. WB trains
            from execute via i0_valid_wb / i1_valid_wb with branch PC and updated
            i0_target_state_wb / i1_target_state_wb.


        1. Branch Predict 2-bit State Encode:

            Each stored entry is a 2-bit saturating counter (br_state_t). Prediction at
            decode uses target_state[1]: 0 -> not taken, 1 -> taken. Training updates are
            computed at MEM by state_LUT from the current state and resolved outcome
            pc_sctrl (1 = taken, 0 = not taken), then written into state_buffer on the
            next i0_valid_wb / i1_valid_wb.

            State encoding:

            | State | Name                     | target_state[1] | Predicted direction |
            |-------|--------------------------|-----------------|---------------------|
            | 2'b00 | strongly not taken       | 0               | not taken           |
            | 2'b01 | weakly not taken         | 0               | not taken           |
            | 2'b10 | weakly taken (default)   | 1               | taken               |
            | 2'b11 | strongly taken           | 1               | taken               |

            bit[1] is what target_predict reads: 0 predicts not taken, 1 predicts
            taken. bit[0] marks how strong that guess is. On the not-taken side, 2'b00
            is strongly not taken and 2'b01 is weakly not taken. On the taken side,
            2'b10 is weakly taken and 2'b11 is strongly taken, with the same direction bit,
            different confidence.

            On cold miss or reset the bank has no entry, so the read path returns
            DEFAULT_STATE 2'b10 (weakly taken). Unseen branches are therefore predicted
            taken on first use, but not with full confidence. After execute resolves the
            branch, the next 2-bit value from the current state and whether the branch 
            was taken, that value is written back into state_buffer on the next valid WB. 

        2. Combinational Dual Read with Forwarding:

            Both ports look up independently from i0_pc and i1_pc when brch_en is
            set for that lane. way_with_bypass reads bank[set][way] unless a valid
            WB in the same cycle targets that slot; then the incoming WB entry wins
            (I0 WB checked before I1 WB). cache_way_read returns the stored 2-bit
            state when valid=1; on miss it returns DEFAULT_STATE. The final output
            mux applies brch_en: branch lanes expose raw_state; non-branch lanes
            force DEFAULT_STATE. Lookups are combinational; predictors see the
            result in the same cycle as the presented fetch PCs.

        3. Sequential Falling-edge Dual Writeback:

            Training commits on the falling clock edge when i0_valid_wb or
            i1_valid_wb is set. The write index is i0_pc_wb / i1_pc_wb; stored
            data is the 2-bit i0_target_state_wb / i1_target_state_wb with valid
            forced to 1. Dual WB in one cycle can update two distinct slots; if both
            trains map to the same set/way, both nonblocking writes fire and the I1
            update is the final value. Because forwarding is evaluated before the
            edge, a train visible on cycle N is readable on port outputs in cycle N
            even though the bank register updates after the edge.

        0. Structure and Specification:

            target_predict is a purely combinational per-lane block instantiated twice
            inside decode_core_struct (u_target_predict_i0 / u_target_predict_i1) beside
            the matching decoder. state_buffer lives in the same struct and feeds
            target_state into each instance; the IF/ID bundle supplies pc,
            pc_target, and per-lane speculation (spec_n). Active when
            branch_active = (brnch_en | jump_en) && !nest_spec_stall.

            Nested speculation guard: if spec_n is set and the slot is a branch or
            jump, the module disables predict/train outputs and asserts spec_stall.
            Top wires each lane's spec_stall into fetch pc.spec0_stall / spec1_stall
            so the PC cannot start a second speculation while one is outstanding.

            Per-instance signal map (I0 shown; I1 is symmetric):

            | target_predict port | Wired from                         | Notes                         |
            |---------------------|------------------------------------|-------------------------------|
            | brnch_en            | decoder brch_en                    | branch or jump                |
            | jump_en             | decoder jump_en                    | JAL / JALR only               |
            | spec_n              | IF/ID spec0_en                     | already speculative           |
            | imm                 | decoder imm                        | sign-extended                 |
            | pc                  | IF/ID i0_pc                        | insn address                  |
            | pc_target           | IF/ID i0_pc_target                 | BTB target from fetch         |
            | target_valid        | IF/ID i0_target_valid_id           | BTB entry hit                 |
            | target_state        | state_buffer i0_brch_state         | 2-bit direction (default on miss) |
            | pred_taken          | -> i0_pred_taken (struct export)   | predict taken                 |
            | pred_valid_wb       | -> i0_pred_valid_wb                | BTB train request             |
            | nest_spec_stall     | -> i0_nest_spec_stall              | freeze PC via spec*_stall     |
            | pc_predict          | -> i0_pc_predict                   | next speculation address      |

            When branch_active is low, pred_taken and pred_valid_wb deassert and pc_predict
            passes pc through unchanged. When nest_spec_stall is high, the same quiet
            outputs apply and PC is stalled via top.

        1. Two Target Predictors for Instruction Parallelism:

            Dual issue is implemented by replicating the same target_predict module
            twice in decode_core_struct with no cross-coupling between lanes. I0 binds
            to u_dec_i0 outputs (valid, brch_en, jump_en, imm) plus i0_pc,
            i0_pc_target, and i0_target_state from state_buffer; I1 binds to the
            matching I1 nets. Both instances evaluate in parallel every cycle. Each
            lane can independently assert predict_taken, wb_valid, and a distinct
            pc_predict while the other lane is quiescent (non-branch) or active on a
            different PC. Throughput is two independent target-predict results per
            cycle; pc_selector in fetch routes each lane's taken predict onto that
            same lane's next-PC base (i0_pred_taken / i1_pred_taken from top) and sets
            the matching sticky spec0 / spec1 flag — not a swap that always puts taken
            on I0 and fall-through on I1.

        2. Branch Target Calculation and Comparison:

            decode_target = align4(pc + imm) = { (pc + imm)[31:2], 2'b00 }.
            use_decode_target = (decode_target != pc_target).
            btb_miss = !target_valid.

            | branch_active | condition                         | pred_valid_wb | pc_predict     |
            |---------------|-----------------------------------|---------------|----------------|
            | 0             | n/a                               | 0             | pc             |
            | 1             | btb_miss                          | 1             | decode_target  |
            | 1             | use_decode_target (stale BTB)     | 1             | decode_target  |
            | 1             | hit && !stale                     | 0             | pc_target      |

            pred_valid_wb flags a BTB train on BTB miss (target_valid=0) or
            decode/BTB target mismatch. Direction state miss uses DEFAULT_STATE.

        3. Predication from 2-bit State and Control:

            Direction prediction is separate from address selection (see state_buffer
            encoding table above).

            | Condition                                      | predict_taken / notes               |
            |------------------------------------------------|-------------------------------------|
            | !branch_active (incl. spec_stall)              | 0; pc_predict = pc                  |
            | branch_active && jump_en                       | 1 (JAL/JALR always taken)           |
            | branch_active && !jump_en                      | target_state[1] (conditional)       |

            Nested speculation:

            | Condition                                      | spec_stall | Predict outputs      |
            |------------------------------------------------|------------|----------------------|
            | spec_n && (brnch_en | jump_en)                 | 1          | disabled (quiet)     |
            | otherwise                                      | 0          | normal branch_active |

            How the loop closes at the top of the core:

            After a branch resolves in memory, the state lookup table chooses the next
            2-bit predictor state for that branch PC. On writeback, decode installs those
            updated states into the state buffer so later fetches see the trained
            direction. Separately, when decode predicts a taken branch or jump, top
            forwards that decision to fetch as predict-taken so the PC selector can
            redirect fetch. If decode sees another branch or jump while fetch is already
            speculative, it raises a spec stall into the PC unit, which freezes the
            program counter until recovery clears the outstanding speculation.

            suppressed. Forwarding on the read path still exposes the winning WB
            value in that cycle before the falling edge. After the edge, subsequent
            reads see the committed value from regs[].
